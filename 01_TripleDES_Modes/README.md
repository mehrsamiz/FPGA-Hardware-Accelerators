# HW03 — Triple-DES Block Cipher with Modes of Operation

## Problem
Implement the DES block cipher from its algorithmic primitives (Feistel network, S-boxes,
key schedule), compose it into Triple-DES (Encrypt-Decrypt-Encrypt with two 64-bit keys),
and wrap it in a mode-of-operation controller supporting ECB, CBC, and OFB on a 256-bit
(4-block) input.

## Approach
- **`DES.v`** — single-round Feistel core: initial/final permutation, 16-round `f`-function
  (expansion → key mix → 8 parallel S-boxes → permutation), and the key schedule (`KS`)
  generating all 16 round subkeys via `PC1`/`PC2` and rotating shifts.
- **`DES_dec.v`** — same datapath, round keys applied in reverse order for decryption.
- **`TripleDES_enc.v`** — chains `DES → DES_dec → DES` with keys `(K1, K2, K1)` for
  Encrypt-Decrypt-Encrypt (EDE) Triple-DES.
- **`TopMode.v`** — FSM that feeds the 4 blocks of the 256-bit input through the Triple-DES
  core one at a time and combines them per mode:
  - **ECB** — each block encrypted independently
  - **CBC** — block XORed with previous ciphertext (IV for block 0) before encryption
  - **OFB** — block XORed with a keystream generated by repeatedly encrypting the IV/feedback
    register (stream-cipher mode)

## Key result
All three modes verified against provided test vectors for a 4-block (256-bit) message;
`tb_TopMode.v` sweeps all three `mode` values and checks output against expected ciphertext.

## What I'd do differently
The block-by-block FSM processes one 64-bit block per ~16-cycle DES call, so the whole
256-bit message takes several times longer than necessary — HW04 explores single-cycle,
multi-cycle, and pipelined versions of this same cipher specifically to address that
latency/throughput trade-off.

## Files
```
rtl/
├── DES.v              — single-round DES encrypt core + key schedule
├── DES_dec.v           — DES decrypt core
├── TripleDES_enc.v     — Triple-DES (EDE) composition
├── TopMode.v            — ECB/CBC/OFB mode controller (FSM)
└── constants/           — S-boxes, P, E, IP, IP⁻¹, PC1, PC2 tables
tb/
├── tb_TopMode.v         — top-level testbench, all 3 modes
├── test_des_dec.v       — DES encrypt/decrypt round-trip check
└── test_triple_enc.v    — Triple-DES encrypt-only check
```
